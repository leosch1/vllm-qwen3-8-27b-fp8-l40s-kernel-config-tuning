Isolated kernel speedup, default vs. tuned, FULLY RANDOMIZED launch order

A new, independent re-run of this experiment's original comparison (see chart.html, kept unchanged) — same 175-point grid, same fixed-tensors-per-point design, same DEFAULT_CONFIG and tuned-configs/ lookup, same 2000 iterations/point. The only change: every one of the 700,000 launches needed (5 shapes × 35 M-points × 2 configs × 2000 iterations) is generated as one flat list, shuffled into a single random order, and executed strictly in that order — bucketed back by (shape, M, config) label only after all launches complete. The original design ran the full default block then the full tuned block sequentially at every point, with tuned always second — discovered in 19's Parts 8-11 to carry an unquantified, sometimes large order/drift bias that inflates whichever config runs second.

Run 1
The original headline result does not survive full randomization. The original claimed +50–70% at small M tapering to single digits, with 0/90 anchors ever negative and 6/85 held-out points negative. This fully-randomized rerun instead shows an overall mean of +6.5% (median +6.7%) — nowhere near +50–70% — with 6/90 anchors now negative (including two real production anchors: gate_up_proj M=512 at −9.5% and M=1024 at −3.4%) and 17/85 held-out points negative, nearly 3× the original count. One thing that did hold up across both designs: M=160's generalization gap (negative in 3/5 shapes here too, worst −18.6% on qkv_proj) — suggesting that specific finding is real, while the smooth "50–70%, always positive" headline picture largely was not.
Run 2 — independent repeat, same design, freshly shuffled
The shape reproduces closely. Same 700,000-launch design, freshly shuffled, run independently minutes later. Every notable feature from Run 1 shows up again at close to the same magnitude: gate_up_proj M=40 (−13.3% → −13.7%), M=512 (−9.5% → −11.2%), M=1024 (−3.4% → −4.0%), M=4096 (+6.6% → +6.5%); qkv_proj M=160 (−18.6% → −17.9%). This is the reproducibility check the sequential-block design never had — two independent runs of this design agree on both the overall level (mean +6.5% → a similarly modest level here) and the specific shape, including which anchors go negative.
Run 3 — cache-cycling variant: weight tensor is NOT held fixed
Same headline level even with genuine cache pressure. Runs 1-2 reuse one fixed weight tensor for all 2000 iterations of both configs at a point (this experiment's original design). This run instead cycles each launch's weight tensor through 64 distinct copies per shape (19's CyclingLaunchCounter design, matching real serving's per-layer weight-switching pattern) — still fully randomized across all 700,000 launches, with a uniformly random copy chosen per launch. Result: overall mean +6.5%, median +6.6% — essentially identical to Runs 1-2's always-warm result, not the more dramatic difference cache pressure made for the GROUP_SIZE_M-isolated singlefix comparison. Consistent with 19 Part 5's finding that the full tuned config's advantage comes mostly from parameters other than GROUP_SIZE_M (BLOCK_SIZE_M, num_warps), which don't care whether the cache is warm.
