gate_up_proj: singlefix vs. tuned, two measurement methods compared

Same question (how does 22's singlefix config compare to plain tuned, isolated to gate_up_proj), computed two different ways from data already on hand. Cross-run: dividing each config's already-logged absolute duration vs. its own separately-run default baseline (the same method Part 6 used for cache-aware/groupfix vs. tuned) — two separate Job runs, chained through two separate default measurements. Paired: a new same-run benchmark (this experiment's Part 8) that directly pits tuned_config(M) against singlefix_config(M) back-to-back in one script execution, counterbalanced exactly like every other comparison here.

The cross-run method is not trustworthy at this resolution. Every point except gate_up_proj's M=2048 (and every point on the other 4 shapes, not shown) is byte-identical between singlefix and tuned — so the true curve should sit flat on 0% almost everywhere with one bump at M=2048. The cross-run line instead drifts as low as −7.6% (M=256) purely from the two runs' own default baselines not quite agreeing (a ~3-8% run-to-run spread neither run's own "sanity check" caught, since each checked its OWN internal consistency, not agreement with a run it hadn't been benchmarked alongside). The paired line, measured in one script execution with the same counter-balanced design as every other chart in this project, sits within ±3pp of zero everywhere except M=2048's clean +2.0% — the real signal, isolated from cross-run noise entirely.
