Isolated kernel speedup, singlefix (22) vs. default, under cache-cycling pressure

Same 175-point grid and cache-cycling methodology as this experiment's other charts — this time for 22's maximally narrow config: byte-identical to the original tuned config everywhere except gate_up_proj's single M=2048 entry, where GROUP_SIZE_M changes from 1 to 16.

Since singlefix is byte-identical to tuned everywhere except one anchor, this curve should track tuned's own cycling curve almost exactly, with a visible bump only right at the changed anchor. Confirmed directly: at every other large-M gate_up_proj point (512/1024/1536/3072/4096), singlefix's speedup vs. default matches tuned's within ±1.5pp (noise, as expected for an identical config) — except at M=2048 itself, where singlefix jumps to +8.9% vs. tuned's +5.8% (+3.1pp, the largest positive delta of any point), and the neighboring held-out M=2560 (nearest anchor 2048, so it inherits the same changed config) also rises (+9.1% vs. tuned's +8.1%). The effect is exactly as localized as the config change that causes it.
