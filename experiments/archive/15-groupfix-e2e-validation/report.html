The mechanism isolated kernel · exp 14

Diffing the two configs surfaces one parameter that isn't a compute-shape choice at all: GROUP_SIZE_M, Triton's L2-cache grid-swizzle knob. Default's value (32) happens to equal its own tile count across M — it groups the entire M range under one fixed weight-tile, so only ~0.64MB of the 89MB weight matrix needs to be resident at a time. Tuned's value (1) disables grouping entirely. The autotuner's benchmark harness always reuses the same warm tensor, so this parameter had zero measurable effect where it was tuned — and landed on the worst possible value for real serving's cold, contended cache.

The e2e validation real serving · exp 15

Deployed all three configs on the real predictor, same node, same day, full concurrency sweep (1–128) — to see whether the isolated fix survives contact with real traffic. The first pass hit a false lead that made everything look noise-sized; corrected, the result is clean and decisive.

The first full pass of this sweep showed every config running at roughly 30–80% of a week-old baseline, and — worryingly — tuned trailing default by a near-constant few percent basically everywhere, not just at high concurrency like the original regression. Thermal throttling, power capping, PCIe link degradation, NVLink, and other GPU-contending pods were all checked directly and ruled out. The real cause was three lines away in the deployment manifest: --enforce-eager, added to the shared servingruntime for an experiment 10 diagnostic tool that was never actually exercised, silently disabling CUDA graph capture/replay for every e2e run since — including this experiment's entire first pass. It took a direct question (“are you sure the pod matches production?”) to prompt the diff that found it.

A constant percentage would mean a proportional compute/bandwidth slowdown. What's actually there is a roughly fixed extra cost per decode step — about +70ms at low concurrency, shrinking smoothly to +32ms at c=128 — diluted as more useful work rides along with it per step. That's exactly the signature of losing CUDA graph replay: eager mode re-pays Python dispatch and kernel-launch overhead on every single step, a cost graphs skip almost entirely. With graphs restored, default matches the original week-old baseline within 99.3–100.0% at every concurrency point — there was no environment drift at all.

Validated, with real margins. tuned vs. default reproduces the original regression almost exactly (+28.0% at c=1 decaying to −4.2% at c=128, vs. the original +27.9%/−4.3%) — a clean, independent replication of this investigation's founding observation, now on a corrected measurement. groupfix vs. default never goes negative anywhere in the sweep, from +28.5% at c=1 down to +2.9% at c=128.
